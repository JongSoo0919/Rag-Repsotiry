# 사내 약어 사전 (Alias Dictionary) 계획

## 왜 필요한가

문서에 `k8s`, `kube`, `쿠버네티스` 로 제각각 적혀도 시스템은 이게 같은 것인 줄 모른다.
특히 **Graph RAG는 이 표기들을 각각 다른 노드로 쪼개** 관계를 분산시킨다.

- **일반 기술용어**(k8s=Kubernetes) → 모델이 이미 안다. 프롬프트/사전으로 쉽게 통일.
- **사내 고유 약어**(SR, CM 등) → 세상 어떤 모델도 모른다. **사람이 사전에 넣어야만** 통일된다.

→ 이 사전은 **모델이 모르는 사내 용어를 통일**하기 위한 것이다.

## 공개/비공개 구조

| 파일 | 커밋 | 용도 |
| --- | --- | --- |
| `data/public/aliases.example.yaml` | ✅ 커밋 | 형식 예시 + 공통 기술용어(kubernetes 등) 실사전 |
| `data/private/aliases.yaml` | ❌ 미추적 | 사내 고유 약어 (사내 자산) |
| `data/private/aliases.candidates.yaml` | ❌ 미추적 | 후보탐지기 출력(검토용) |

로더는 **public + private를 합쳐** 쓰며, 겹치면 **private가 우선**한다.

## 사전 형식

```yaml
- canonical: Kubernetes      # 통일할 정식 이름(대표 표기)
  aliases: [k8s, kube, 쿠버네티스]   # 같은 것으로 볼 표기들(대소문자 자동 무시)
  desc: 컨테이너 오케스트레이션 플랫폼   # (선택) 메모
```

## 만드는 흐름 — 반자동 후보탐지

```text
[1] Confluence 원문을 data/private/ 에 .md 로 저장 (사내 자산·git 미추적, public에는 공개 예시만)
[2] 후보 탐지기 실행
      .venv/bin/python -m preprocessing.abbrev_candidates
    → data/private/aliases.candidates.yaml 생성
      · "정식명칭(약어)" 패턴 수집 (예: "서비스 요청(SR)")
      · 반복되는 대문자 약어 토큰 수집 (예: SR, CM, WAS)
      · 이미 사전에 있는 표기는 제외
[3] 사람이 검토: canonical(정식명칭) 채우기 / 약어 아니면 삭제
[4] 확정 항목을 data/private/aliases.yaml 로 이동
[5] 그래프 재적재 → 자동 통일 저장
      .venv/bin/python -m graph.ingest
```

핵심: **기계가 후보를 모으고, 사람이 승인**한다. 맨손으로 떠올리는 것보다 누락이 적다.

## 코드 연결 (적용 범위: 우선 그래프만)

정규화 함수 `preprocessing.aliases.normalize()` 를 그래프 트랙에 연결:

| 위치 | 파일 | 하는 일 |
| --- | --- | --- |
| 그래프 적재 | `graph/ingest.py` (`apply_aliases`) | 노드 id를 정식명칭으로 통일 + 같은 id로 합쳐진 중복 노드 병합(임베딩 낭비 방지) |
| 그래프 질의 | `graph/query.py` (`find_question_entities`) | 질문에서 뽑은 표기도 통일해서 노드 매칭 |

> Vector 트랙은 이번 범위에서 제외(임베딩이 표기 차이를 어느 정도 견딤). 추후 질의-확장 방식으로 연결.

## 정규화 규칙

- **통째로 일치할 때만** 바꾼다(부분일치 X). `USRID` 는 `SR` 로 안 바뀐다.
- **대소문자 무시**. `K8S` → `Kubernetes`.
- 사전에 없으면 **원래 값 그대로**(양끝 공백만 제거).
- 함부로 합치지 않는다: 다른 것을 같다고 뭉개는 위험 때문에 **사람이 검토한 명시적 사전**만 신뢰.
