# 2026.07.09 3일차

## 결론

오늘 작업으로 **Graph RAG를 튜토리얼에서 실데이터 PoC로 완성**하고, 이어서 **Vector·Graph·Hybrid 3트랙 체계**를 갖췄다.

핵심 성과:
- Graph RAG: 하드코딩 제거 → 실제 문서에서 LLM이 Entity/관계를 추출해 Neo4j에 저장하고, 관계 탐색 결과를 LLM으로 답변
- Graph 엔티티 진입을 CONTAINS 키워드 매칭 → **LLM 추출 + 임베딩 코사인 매칭**으로 교체 (표현 민감성 해결)
- 데이터를 공개/비공개 폴더로 분리 (`data/public` 커밋, `data/private` gitignore)
- Vector를 LangChain 단일 트랙으로 정리
- **Vector→Graph 순차 하이브리드** 신설
- 라이브 스모크 테스트로 3트랙 실동작·품질 확인

## 전체 흐름

```text
data/public + data/private (.md)
   ├─ Vector 트랙 → 청킹 → 임베딩 → Qdrant
   └─ Graph 트랙 → LLM Entity/관계 추출 → 노드+임베딩 → Neo4j

질문
   ├─ vector.query : 의미 유사 청크 검색 → LLM 답변
   ├─ graph.query  : LLM 엔티티 추출 → 노드 임베딩 매칭 → 1~2홉 관계 → LLM 답변
   └─ hybrid.query : ①vector 검색 ②그 맥락으로 graph 진입 보강·관계 확장 ③둘 종합
```

## 내가 한 행동

### 1. 저장소 재편 정리 + 민감정보 스캔

- 이전 세션에서 `src/` → `vector/` 이동 + `graph/` 추가가 커밋 전 상태였음. 논리 단위로 커밋 정리.
- git 히스토리 전체에 API 키·이메일·내부 URL·회사명이 들어갔는지 스캔 → **검출 0건**. 비공개 원문은 `data/private`·`private_reports`로 gitignore 처리 확인.

### 2. Graph RAG 완성 (튜토리얼 → 실데이터)

세 가지 격차를 메웠다.

```text
① 데이터  : 하드코딩 K8s dict → data/*.md 로딩(load_documents)
② 답변    : if-분기 하드코딩 → 그래프 탐색 결과를 LLM에 넣어 생성
③ E2E     : Neo4j 실기동으로 ingest→query 검증
```

- `graph/documents.py`: 문서 로딩 + LLM Entity/관계 추출 책임만 남김. LLM 키 없으면 명확한 에러(가짜 fallback 제거).
- `graph/query.py`: 하드코딩 답변 제거 → 관계 context를 LLM에 전달.

### 3. 공개/비공개 데이터 분리 + K8s 샘플 복원

- `data/public/` (커밋) / `data/private/` (gitignore) 폴더 분리.
- 초기 튜토리얼의 K8s 3문서(Pod/Deployment/Service-JS)를 `data/public/k8s-sample.md`로 복원 → "Deployment를 외부 통신하려면?" 질문이 `Deployment→Pod←Service-JS` 관계로 답변됨을 확인.
- `load_documents()`를 `data/` 재귀(rglob)에서 **`public`·`private` 폴더 명시 지정(비재귀) + 심볼릭 링크 차단**으로 변경(의도치 않은 .md 흡수 방지).

### 4. Vector 다중 문서 인덱싱

- Vector가 단일 파일만 읽던 것을 `public`+`private` 전체로 확장.
- `split_by_sections`가 숫자 섹션(`1.`)뿐 아니라 마크다운 헤더(`##`)도 인식하도록 확장(K8s 문서 청킹).

### 5. Graph 엔티티 진입 개선 (핵심)

문제: 기존 진입이 `toLower(question) CONTAINS e.id` 같은 **키워드 부분일치**라 표현에 민감. "표시되지 않아"라고 물으면 엉뚱한 주변 노드([Log Panel, Loki, Alloy])를 잡았다.

해결: 표준 Entity Linking 흐름으로 교체.

```text
질문 → LLM으로 엔티티 추출 → 추출어 임베딩 → 노드 임베딩과 코사인 매칭 → 진입
      (실패 시 lexical CONTAINS로 fallback)
```

- `graph/embedding.py`(신규): Gemini 임베딩 헬퍼.
- `graph/ingest.py`: 노드에 `embedding` 프로퍼티 저장(`enrich_nodes_with_embeddings`). 임베딩 계산을 clear보다 먼저 해 그래프 유실 방지.

### 6. Vector LangChain 단일화

- 직접구현(`google-genai`+`qdrant-client` raw)과 LangChain 두 트랙이 공존하던 것을 **LangChain 단일 트랙**으로 정리.
- `langchain_ingest/query`를 정본 `ingest.py`/`query.py`로 통합, `web_app`을 retriever+Document 형태로 재작성.
- 의도: `graph`(raw SDK) vs `vector`(LangChain)를 대조 학습셋으로.

### 7. Hybrid RAG (Vector→Graph)

- `hybrid/` 신규 패키지. `vector.query`·`graph.query`를 재사용해 순차 결합.
- Bridge 단계에서 질문+벡터청크로 그래프 진입을 보강하되, lexical fallback엔 원 질문만 넘겨 seed_text 오염 방지.
- 각 단계 부분 실패 격리(한쪽 저장소가 죽어도 다른 한쪽으로 저하 동작).

### 8. 웹 UI 예시 질문 + README 개편

- 3개 웹(`:8001/8002/8003`) 모두에 트랙 특성에 맞는 **좋은/나쁜 예시 질문**을 버튼으로 추가(클릭 시 자동 입력).
- README를 GitHub 상위권 프로젝트 관례(배지·목차·mermaid 다이어그램)로 전면 개편.

### 9. 라이브 스모크 테스트

- `graph.ingest`(노드 임베딩 채움) + `vector.ingest`(재색인) 후 실동작 검증.
- **"로그 시각화가 표시되지 않아"** → 예전엔 엉뚱한 노드, 이제 `Loki Dashboard` 정확히 잡고 인과+조치 완답 (진입 개선 증명).
- 대표 질문을 3트랙 비교 → Hybrid가 벡터의 서술 디테일 + 그래프의 관계 근거를 함께 낸 것을 확인.

## 오늘 이해한 개념

### Graph RAG의 "진입"은 검색 패러다임과 별개

관계 그래프가 잘 만들어져 있어도, 그 관계로 **들어가는 문(엔티티 진입)이 부실하면** 소용없다. 진입을 키워드 매칭 → 의미(임베딩) 매칭으로 바꾸니 표현 차이에 강해졌다.

### Vector가 "조각나서 못 한다"는 오해

Vector는 청크를 독립 저장하지만, 검색이 top-k(여러 청크)를 함께 가져오고 **LLM이 그 조각들을 이어붙인다**. 작은 문서는 청크가 거의 다 검색돼 관계 추론도 그럭저럭 된다.

### 하이브리드의 진짜 가치

Vector→Graph 순차는 **벡터의 의미검색이 그래프의 진입 약점을 보완**하는 구조다. 표현이 문서와 다르면서 관계 추론이 필요한 질문에서 단독 트랙보다 강하다.

### vector vs graph는 "추상화 수준"도 다르다

vector(LangChain)와 graph(raw SDK)는 검색 방식뿐 아니라 프레임워크 사용 유무도 다르다 → 두 축이 동시에 바뀌는 "변수 혼입"이 있음(순수 LangChain 효과만 보려면 유의).

### 쿼터: 일일 vs 분당

Gemini 무료 `generate_content`는 **하루 20회 + 분당 제한**이 함께 있다. 세션 중 429는 일일 소진이 아니라 분당 폭주였고, 호출을 띄엄띄엄 하면 정상 동작했다.

## 실행 명령

```bash
# 적재
.venv/bin/python -m graph.ingest      # 문서 → Neo4j (노드 임베딩 포함)
.venv/bin/python -m vector.ingest     # 문서 → Qdrant

# 질의 (3트랙)
.venv/bin/python -m vector.query '질문'
.venv/bin/python -m graph.query  '질문'
.venv/bin/python -m hybrid.query '질문'

# 웹
.venv/bin/uvicorn vector.web_app:app --port 8001
.venv/bin/uvicorn graph.web_app:app  --port 8002
.venv/bin/uvicorn hybrid.web_app:app --port 8003
```

## 완료 기준

```text

라이브 스모크로 3트랙 실동작이 확인된다.
```
